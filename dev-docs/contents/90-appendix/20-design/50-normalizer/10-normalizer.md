## 厳密な JSON パーサとの二つの違い

`.json` を YAML 1.2 のリーダで読むので（本文の「`.json` も YAML のリーダで読む」）、厳密な JSON パーサとは挙動が二点違う。どちらもこのままにする。

- **`.json` の中に YAML の書き方が混ざっても読める（緩い側）。** `docs/` は `.json` を JSON として受け付けるとしか書いておらず、YAML の書き方が通ることは約束していない。これを弾くには JSON 専用のパーサを前に置く必要があり、本文の判断と衝突する。
- **重複したキーはエラーになる（厳しい側）。** JSON の仕様（RFC 8259）は重複キーの扱いを実装に任せており、多くの実装は黙って後の値を採る。黙って値が消えるより止まるほうが安全なので、こちらを保つ。エラーは他の構文エラーと同じく、位置つきで利用者に示される。実際に起きればエラーを見て分かるので、`docs/` には書かない。
